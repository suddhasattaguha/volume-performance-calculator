Config: factors and instance limits

Defaults come from vendor documentation and general practice (confidence A = official doc, B = vendor KBA or Q&A, C = secondary, E = empirical, to calibrate). Overwrite any value with your own landscape figure, for example your Solace service class, S/4 work processes or CI capacity. Changed values are highlighted and stored in this browser only.

How the evaluation works

  1. Describe the interface in quantities. Volume, size (as lines), processing weight, latency need, run frequency, growth. Each quantity is shown with its band on the framework scale (L1–L5, C1, D1, D3, P1).
  2. The bridge turns quantities into measures with fixed formulas (trail table). The same inputs always give the same measures.
  3. Each pattern is a chain of layers. Each layer is checked against its limit from Config. Each check gets a zone.
  4. Roll-up: any Beyond → Beyond · two or more Adapts → Fragile · one Adapt → Adapt · otherwise Fit.
  5. Three runs: today, 3 years (growth applied), and the mass event as its own scenario on top of the average daily load.

Core formulas

Peak rate R (records/h) = users × transactions per user × countries (or Extrapolation, or direct) Average rate = R ÷ peak-to-average ratio Daily volume = R ÷ peak-hour share Record size, typical = header + typical lines × KB per line + attachment Record size, largest = header + max lines × KB per line + attachment Records per message (rpm) = continuous: as entered · scheduled: records per run Records per run = 15 min: R ÷ 4 · hourly: R · daily: daily volume Messages per hour M = R ÷ rpm Message size = rpm × typical record (largest: (rpm−1) × typical + largest record) Metered weight = ceil(message size ÷ metering slice) In flight (Little's law) = R ÷ 3600 × processing seconds per record Drain capacity (records/h)= capacity in flight ÷ seconds per record × 3600 Years to limit = 3 × ln(limit ÷ value) ÷ ln(3-year growth)

Zoning rules per check

Size at a component ≤ comfortable size → Fit · ≤ hard cap → Adapt · above → Beyond Capacity at a layer in flight ≤ comfort % × capacity → Fit · ≤ capacity → Adapt above capacity: with a leveller and average ≤ drain → Adapt (backlog drains) otherwise → Beyond Metering (BTP) weight ≤ ratio threshold → Fit · above → Adapt (cost) · monthly over quota → Beyond Sync time within real-time budget or comfort % of HTTP ceiling → Fit · ≤ ceiling → Adapt · above → Beyond Records into S/4 1 → Fit · ≤ $batch limit → Adapt · ≤ OData mass limit: Adapt async / Beyond sync · above → Beyond Mass event on daily road above own-road threshold → Beyond (separate road, CP-01)

Ordering (C3) is parked. Datasphere is not profiled yet, so it's left out. The empirical values (E) on the Config tab are the ones to calibrate first: CI and S/4 capacities, processing times, size defaults.
